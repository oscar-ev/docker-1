Docker via PowerShell

Três atividades práticas e progressivas: dos comandos essenciais do Docker até subir um servidor web de verdade, acessível no navegador.

Pré-requisito: Docker Desktop Terminal: PowerShell (Windows) Duração total: ~110 min

Regra de ouro — um comando por vez

O PowerShell dos laboratórios da UMC não aceita dois comandos na mesma linha. Cada bloco de código abaixo é um único comando: rode um de cada vez (use o botão copiar), aperte Enter e espere terminar. Nunca junte comandos com &&, | ou ; — se aparecer erro de sintaxe, foi mais de uma linha colada junta.

Quatro conceitos antes de começar

Entender estas quatro ideias faz todo o resto encaixar.

📦Imagem
Um molde congelado, pronto para uso (ex: nginx, ubuntu). É o que você baixa do Docker Hub. Não roda sozinha — serve de base.
🐳Container
Uma cópia viva de uma imagem, em execução. É o "mini-computador" isolado onde as coisas acontecem. De uma imagem você cria quantos containers quiser.
🔌Porta (-p)
Uma ponte entre o seu PC e o container. -p 8080:80 liga a porta 8080 do seu PC à porta 80 interna — é assim que o navegador alcança o site de dentro.
🔗Volume (-v)
Uma pasta compartilhada entre o seu PC e o container. O que você edita no Windows aparece na hora dentro do container — sem reiniciar nada.

Analogia rápida

Imagem é a receita; container é o prato pronto feito a partir dela. Você baixa a receita uma vez e cozinha quantos pratos quiser.

Pré-requisito — verificar o Docker

Abra o PowerShell (não precisa ser administrador) e rode o comando.

🪟 PowerShell — sua máquina
PowerShell · Windows
PS>docker version
Precisam aparecer as linhas Client e Server com versões.

Se der erro de conexão, abra o Docker Desktop e espere o ícone da baleia ficar verde antes de tentar de novo.

01

Comandos essenciais do Docker

Baixar imagens, iniciar e parar containers, listar o que está rodando e limpar o ambiente.

docker pulldocker rundocker psdocker stopdocker rmdocker images
~30 min
ObjetivoAo final você saberá baixar imagens do Docker Hub, iniciar e parar containers, ver o que está rodando e limpar tudo.
1.1Ver informações do ambiente
🪟 PowerShell
PowerShell · Windows
PS>docker info

docker info mostra o estado do ambiente: quantos containers e imagens existem, drivers de rede e armazenamento. Bom para confirmar que está tudo no ar.

1.2Baixar sua primeira imagem
🪟 PowerShell
PowerShell · Windows
PS>docker pull hello-world

pull baixa a imagem do Docker Hub (repositório público). hello-world é mínima, feita só para testar o ambiente.

1.3Listar as imagens baixadas
🪟 PowerShell
PowerShell · Windows
PS>docker images

Lista as imagens no seu disco, com REPOSITORY, TAG (versão), IMAGE ID e SIZE.

1.4Executar o Hello World
🪟 PowerShell
PowerShell · Windows
PS>docker run hello-world
Hello from Docker!

run cria e inicia um container a partir da imagem. O hello-world imprime a mensagem e encerra sozinho.

1.5Rodar o nginx em segundo plano
🪟 PowerShell
PowerShell · Windows
PS>docker run -d --name meu-nginx nginx

-d (detached) roda em background, sem prender o terminal. --name meu-nginx dá um apelido ao container. nginx é um servidor web leve (baixado na hora, se preciso).

1.6Ver o que está rodando
🪟 PowerShell
PowerShell · Windows
PS>docker ps
PowerShell · Windows
PS>docker ps -a

docker ps mostra só os containers em execução. docker ps -a mostra todos, inclusive os já parados (como o hello-world, com status Exited).

1.7Parar e remover (um por vez)
🪟 PowerShell — quatro comandos, um por vez
PowerShell · 1 de 3
PS>docker stop meu-nginx
PowerShell · 2 de 3
PS>docker rm meu-nginx
PowerShell · 3 de 3
PS>docker rmi hello-world

stop desliga o container com segurança; rm apaga o container (a imagem continua no disco); rmi apaga a imagem.

Atalho

docker rm -f meu-nginx para e remove num comando só, com a flag -f (force). Continua sendo uma linha única — pode usar.

Checklist — Atividade 1

  • Docker verificado com docker version sem erros
  • Imagem hello-world baixada e executada
  • nginx rodando em background com nome personalizado
  • Diferença entre docker ps e docker ps -a entendida
  • Container parado, removido e imagem apagada
02

Container Ubuntu — manipulação de arquivos

Entrar num container Ubuntu interativo, criar pastas e arquivos, escrever e ler conteúdo, e sair com segurança.

-it bashmkdirtouchecho / catexitdocker exec
~35 min
ObjetivoTrabalhar dentro de um container Linux como se fosse um servidor de verdade — criando, editando e lendo arquivos, sem instalar nada no Windows.
2.1Entrar num Ubuntu interativo
🪟 PowerShell
PowerShell · Windows
PS>docker run -it --name meu-ubuntu ubuntu bash
root@a3f1c2d4e5b6:/# ← agora você está DENTRO do container

-i mantém a entrada aberta; -t dá a interface de terminal; juntos (-it) te deixam digitar dentro do container. bash é o terminal que abre.

O prompt mudou

Saiu de PS> para root@...:/#. Agora você está no Linux, dentro do container. Os próximos passos (2.2 a 2.5) rodam aqui dentro.
2.2Onde estou? Criar estrutura de pastas
🐧 Dentro do Ubuntu — root@…
Ubuntu · root@…
#pwd
Ubuntu · root@…
#mkdir -p /minha-aula/documentos/notas
Ubuntu · root@…
#ls -la /minha-aula

pwd mostra onde você está (deve ser /). mkdir -p cria toda a árvore de pastas de uma vez. ls -la lista com detalhes (permissões, tamanho, data).

2.3Criar e escrever num arquivo
🐧 Dentro do Ubuntu — root@…
Ubuntu · root@…
#cd /minha-aula/documentos
Ubuntu · root@…
#echo "Olá, Docker! Aula de containers." > arquivo1.txt
Ubuntu · root@…
#echo "Segunda linha." >> arquivo1.txt
Ubuntu · root@…
#cat arquivo1.txt
Olá, Docker! Aula de containers. Segunda linha.

echo "texto" > arquivo escreve no arquivo (sobrescreve). >> acrescenta ao final sem apagar. cat mostra o conteúdo. Aqui o > funciona porque estamos no bash do Ubuntu, não no PowerShell.

2.4Copiar, renomear e listar
🐧 Dentro do Ubuntu — root@…
Ubuntu · root@…
#cp arquivo1.txt notas/copia.txt
Ubuntu · root@…
#mv arquivo1.txt renomeado.txt
Ubuntu · root@…
#ls -R

cp copia (mantém o original); mv move ou renomeia (o original some do nome antigo); ls -R lista tudo, inclusive subpastas.

2.5Sair e reentrar no container
🐧 Dentro do Ubuntu — root@…
Ubuntu · root@…
#exit
O prompt volta a ser PS> — você saiu do container.
🪟 PowerShell — de volta na sua máquina
PowerShell · 1 de 2
PS>docker start meu-ubuntu
PowerShell · 2 de 2
PS>docker exec -it meu-ubuntu bash

exit fecha o bash; como era o processo principal, o container também para. docker start liga de novo — seus arquivos continuam lá. docker exec -it ... bash entra num container já rodando (diferente do run, que cria um novo).

Sair sem parar o container

Dentro do container, Ctrl+P seguido de Ctrl+Q solta o terminal sem encerrar o container. Para esta atividade, pode usar exit normalmente antes de ir à próxima.

Checklist — Atividade 2

  • Ubuntu iniciado no modo interativo (-it bash)
  • Pastas criadas com mkdir -p
  • Arquivo criado, escrito e lido com echo e cat
  • Arquivo copiado e renomeado com cp e mv
  • Saída com exit e reentrada com docker exec
03

Servidor web com página personalizada

Criar uma página HTML, servi-la por um container nginx com mapeamento de porta e volume, e acessar pelo navegador.

-p porta-v volumenginxlocalhost:8080docker logs
~45 min
ObjetivoSubir um servidor web nginx no Docker, mapear a porta para o seu PC e servir uma página HTML feita por você — acessível em localhost:8080.
3.1Criar a pasta do site
🪟 PowerShell
PowerShell · Windows
PS>mkdir C:\docker-site

Cria a pasta no seu PC que vai guardar os arquivos do site. É essa pasta que vamos compartilhar com o container (o volume).

3.2Criar a página index.html

Há dois jeitos. O Jeito A (recomendado) é mais visual e não depende de digitar código no terminal. O Jeito B é um atalho de uma linha, caso prefira.

Jeito A — pelo Bloco de Notas (recomendado)

1. Abra o PowerShell e rode o comando abaixo para abrir o Bloco de Notas já no arquivo certo:
🪟 PowerShell
PowerShell · Windows
PS>notepad C:\docker-site\index.html

2. O Bloco de Notas pergunta se quer criar o arquivo — clique em Sim. 3. Cole o conteúdo abaixo, salve (Ctrl+S) e feche.

index.html — cole isto no Bloco de Notas
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <title>Meu Container Web</title>
</head>
<body style="font-family:sans-serif;text-align:center;padding:60px">
  <h1>🐳 Docker funcionando!</h1>
  <p>Servidor web rodando dentro de um container nginx.</p>
  <p>Feito por: SEU NOME AQUI</p>
</body>
</html>

Jeito B — atalho de uma linha

Se preferir não abrir o editor, este comando cria o arquivo direto. É uma linha única — funciona no PowerShell restrito:
🪟 PowerShell
PowerShell · Windows — uma linha só
PS>Set-Content C:\docker-site\index.html "<h1>🐳 Docker funcionando!</h1><p>Feito por SEU NOME</p>"

Set-Content escreve o texto num arquivo. Aqui está tudo numa linha só, sem o bloco multilinha (@"..."@) do roteiro antigo — assim não esbarra na limitação do PowerShell.

3.3Subir o nginx com porta e volume
🪟 PowerShell
PowerShell · Windows — uma linha só
PS>docker run -d --name servidor-web -p 8080:80 -v C:\docker-site:/usr/share/nginx/html nginx

-d roda em background. --name servidor-web nomeia o container. -p 8080:80 liga a porta 8080 do seu PC à porta 80 do nginx. -v C:\docker-site:/usr/share/nginx/html espelha a sua pasta dentro do container — qualquer mudança no HTML aparece na hora.

3.4Conferir e abrir no navegador
🪟 PowerShell
PowerShell · Windows
PS>docker ps
PORTS: 0.0.0.0:8080->80/tcp NAMES: servidor-web
PowerShell · Windows
PS>Start-Process "http://localhost:8080"

No docker ps, confirme a porta 8080->80. Start-Process abre o navegador direto na página — você verá seu HTML servido pelo nginx. Ou simplesmente abra http://localhost:8080 no navegador.

3.5Atualizar o site em tempo real
🪟 PowerShell
PowerShell · Windows — uma linha só
PS>Add-Content C:\docker-site\index.html "<p>Linha nova em tempo real!</p>"

Add-Content acrescenta texto ao arquivo. Como usamos volume (-v), a mudança aparece na hora ao atualizar o navegador (F5) — sem reiniciar o container. Teste!

3.6Ver os logs de acesso
🪟 PowerShell
PowerShell · Windows
PS>docker logs servidor-web
172.17.0.1 - - "GET / HTTP/1.1" 200

docker logs mostra os acessos ao nginx. Cada vez que você abre a página, aparece uma linha com o horário, o método (GET) e o código de resposta (200 = OK).

3.7Encerrar (um por vez)
🪟 PowerShell — dois comandos, um por vez
PowerShell · 1 de 2
PS>docker stop servidor-web
PowerShell · 2 de 2
PS>docker rm servidor-web

O roteiro antigo juntava os dois com &&, que o PowerShell da UMC não aceita. Aqui estão separados: primeiro stop, depois rm.

Desafio extra

Descubra o IP do seu PC com ipconfig e peça a um colega para abrir http://SEU-IP:8080 no navegador dele. (O firewall do Windows precisa liberar a porta 8080.)

Checklist — Atividade 3

  • Página index.html criada em C:\docker-site
  • nginx iniciado com -p (porta) e -v (volume)
  • Site aberto em http://localhost:8080
  • Página atualizada em tempo real sem reiniciar
  • Logs vistos com docker logs
  • Container parado e removido
